## 一張訂單會走過的四關

1. **收單驗證** — 檢查訂單格式(要有訂單編號、地區只能是本地/離島、至少一項商品、數量是正整數)。不合格 → 直接標記 `failed`,不重試。
2. **保留庫存 + 鎖定單價** — 從庫存扣下商品,並把「這張單要用的單價」拍照存起來(鎖價)。缺貨或找不到商品 → 直接 `failed`,不重試。
3. **計算金額** — 用第 2 關鎖住的單價算折扣、稅、運費。
4. **交給物流出貨** — 選物流商、送出。失敗會重試,詳見下面。

## A.出貨失敗:客戶會遇到什麼

**正常失敗處理流程:**
- 系統會**自動重試,最多 3 次**,間隔是 ~0.2 秒、~0.4 秒(等於**整個重試在約 1 秒內就跑完**)。
- 3 次都失敗 → 訂單被丟進「死信佇列(dead-letter)」等**人工處理**;**庫存會退回**目錄(別人可以買),這張單**不會出貨**。
- 客戶端拿到的收據狀態是 `dead_lettered` + 失敗原因(例:carrier down),**上面沒有金額**。

**這裡有幾個你該知道的營運風險(建議跟工程確認):**

| 風險 | 影響 |
|---|---|
| 重試窗口極短(~1 秒) | 只能吸收「瞬斷」。物流商只要當機超過一兩秒,訂單就直接進死信,不會多等。 |
| 只重試**同一家**物流商 | 沒有自動改用別家(no failover)。某家 API 掛了 → 這批單全進死信。 |
| 重試可能造成**重複出貨** | 如果物流其實已收到、只是回應逾時,系統會再送一次。是否會重複,取決於物流端有沒有防重複機制——程式裡看不到,要問。 |
| 只有「重試用完」這種失敗被接住 | 若物流回的是「致命錯誤」而非「可重試」,整筆會直接中斷:**庫存不會退、也不進死信、客戶拿不到收據**。需確認物流回應的錯誤類型。 |

## B.價格變動:客戶會遇到什麼

**鎖價機制:** 下單當下會把單價「拍照」鎖住 **120 秒**。這 120 秒內同一張單重複處理,價格不變——這是好的。

**超過 120 秒後**,同一張單若再被系統處理(例如延遲的重試、佇列重送、手動重跑),系統會**用「當下的目錄價」重新計算**,金額可能跟原本報價**不一樣(變高或變低)**。而且:

- ⚠️ **改價是「默默」發生的**。程式內部雖然有一個「需重新報價」的旗標,但**目前沒有任何地方去讀它**,所以不會通知客戶、也不會提醒營運。客戶可能就這樣被換了個價格。
- ⚠️ **我確認到一個 bug:120 秒後重跑同一張單,庫存會被「重複扣一次」。** 例如一張 3 件的訂單,第二次處理又扣了 3 件,原本那 3 件**沒有退回**。後果:熱門商品的可售庫存會莫名變少,**其他客戶可能被誤判「缺貨」而下單失敗**(而缺貨是不重試、直接失敗的)。

> 白話說:這系統很強調「同一張單重複處理不會出事(idempotent)」,代表它本來就預期同一張單會被跑第二次。問題是這個保護只在 120 秒內有效,超過就會同時觸發「默默改價」和「重複扣庫存」。

---

## C.一個更大的隱憂:重複出貨

「鎖價 120 秒 / 同單不重扣庫存」只保護了**庫存和價格**,**沒有保護「出貨」這一步**。程式裡**沒有「這張單已經出過貨了嗎?」的檢查**。所以同一張單只要被系統處理兩次(不管 120 秒內或外),就會**出貨兩次**。

- 對客戶:可能**收到兩份貨**。
- 對營運:重複成本、退貨與客訴處理。

這通常在「佇列重送」「上游逾時後重試」「人工重跑」時發生,實務上並不罕見。

## 定價規則(方便你回答客服/客戶常見問題)

- **折扣不疊加,只取一個**:商品滿 5000 元 → 打 **7 折**;未滿 5000 → 打 **9 折**。
- **免運看「折扣前」金額**:折扣前商品滿 8000 元免運。所以就算打完折低於 8000,**仍然免運**(對客戶有利)。
- **稅(5%)只對「折扣後」金額課,運費不課稅**。
- 小提醒:因為「滿 5000 才有 7 折」,金額卡在 5000 上下時會出現「**多買一點反而更便宜**」(4999 元打 9 折 ≈ 4499;湊到 5000 打 7 折 = 3500)。行銷上可利用,也可能被客戶拿來鑽。
